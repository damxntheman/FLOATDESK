# Contributing

Thanks for helping make phone-first remote desktop easier and safer.

1. Discuss substantial scope changes in an issue first.
2. Prefer small pull requests with clear reproduction steps.
3. Run `npm test` before submitting.
4. State which devices/browsers were actually tested. Never label assumed behavior as validated.
5. Avoid telemetry, hidden input access, credential collection, public relay infrastructure, and insecure defaults.
6. Never upload recordings, pairing tokens, TLS keys, or personal screen content in issues.
7. Keep experimental APIs behind clear user actions and document failure states.

Code of conduct: be respectful, assume good intent, and address security reports privately through the process in SECURITY.md.
